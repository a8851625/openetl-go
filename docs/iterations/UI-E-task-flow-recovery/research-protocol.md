# UI-E.1 匿名任务走查协议（待外部参与者）

> 状态：`blocked_external`（2026-09-26）  
> 目的：为 UI-E 的首次成功与故障恢复闭环建立行为基线；不是满意度问卷，也不以内部贡献者自测代替目标用户证据。

## 所需外部输入与负责人

| 输入 | 最低要求 | 建议 owner | 不可替代原因 |
| --- | --- | --- | --- |
| 参与者 | 3–5 名小团队中兼任数据运维的应用/后端工程师；至少 3 名此前未使用过 OpenETL | 产品 owner / 用户研究协调人 | 内部熟练贡献者已知页面/术语，不能代表首次使用行为 |
| 隔离环境 | 可重置的 MySQL、ClickHouse、OpenETL app、DLQ 故障注入环境；仅合成 `orders` 数据 | 工程 owner | 不能在生产库、真实凭据或业务数据上执行测试/重放 |
| 同意与记录方式 | 允许记录匿名行为笔记和耗时；录屏若有必须由研究方保管、不提交仓库 | 研究协调人 | 任务记录需要可复核，但仓库不得存 PII、录屏、凭据或真实配置 |

**解除阻塞的验证**：产品 owner 提供至少 3 位合格参与者的已约时间段，以及一个可重置的隔离环境；每位完成下面五类任务后，研究协调人交付不含身份信息的观察矩阵。只有达到 3 位有效样本，UI-E.1 才能从 `blocked_external` 转为可验证；达到 5 位前可继续收集以降低偶然性。

## 研究前置与安全清单

1. 使用独立、可丢弃的容器/数据库；不得使用生产 DSN、API token、客户表、真实订单或真实 email/手机号。
2. 每轮开始前重置数据库、checkpoint、DLQ 和浏览器 storage；记录环境版本与任务开始时间。
3. 观察者只能回答环境操作问题（例如“浏览器已恢复”），不能告诉参与者应点什么、该选哪个 connector 或如何修复。
4. 记录使用匿名编号 `P01`–`P05`；不要记录姓名、公司、IP、录屏文件路径、凭据、原始 YAML 或错误 payload。
5. 参与者可随时停止；停止按“未完成”记录，不追问其个人信息。

## 任务脚本

按顺序执行；每项先读出任务目标，随后静默观察。任务之间允许参与者使用 UI 中可见的帮助与文档。

| # | 任务 | 起始状态 | 完成判据 | 必记行为 |
| --- | --- | --- | --- | --- |
| T1 首条交付 | 空环境、合成 MySQL `orders`、可写 ClickHouse | 建立 `orders → ClickHouse` 管道，完成 preflight，启动并用 UI 说明首批写入/ checkpoint 的证据 | 是否打开/编辑 YAML；首个误点；何时请求帮助；是否能说明写入模式 |
| T2 故障恢复 | 已注入 sink timeout 和 20 条合成 DLQ；管道停在安全的可恢复状态 | 说明根因、修复路径、是否应先验证；完成 dry-run/replay 并说明 remaining backlog/重复边界 | 是否直接误点 replay；是否能找到修复证据；从问题入口到明确下一步的时间 |
| T3 小屏值守 | 浏览器设为 390×844，保留同一隔离故障 | 测试连接、查看失败，并定位安全 replay 入口 | 是否发生整页横向滚动；是否找不到操作；键盘/触屏障碍 |
| T4 动作文案 | 提供同一 issue 上 `Diagnose` / `Locate` 或当前实际等价动作 | 选择最能回答“下一步做什么”的动作并说明原因 | 首击；点击前说法；是否理解目标对象与结果 |
| T5 指标解释 | 显示真实/合成但服务端返回的 running、health、checkpoint age、CDC lag、DLQ、累计 records | 回答“是否在推进、依据是什么、现在先处理什么” | 将累计当作健康/推进的误解；所引用指标；需要的补充信息 |

## 汇总与决策门槛

完成后仅提交下列匿名聚合内容：

- 每项任务的完成/放弃数、中位耗时、首个错误类别、协助次数范围、YAML 使用数；
- 支持、推翻或仍未证实的假设（至少一个反例）；
- 是否达到 UI-E.2 逐步披露的决策门槛；
- 与 UI-E.3 API 契约 preflight 的已知/未知关系；
- 若没有达到门槛，明确下一轮研究问题，不把偏好评价转为功能承诺。

研究完成前，UI-E.2/UI-E.4/UI-E.5 不得实施。API 只读契约盘点可在参与者安排期间准备，但不可以替代上述行为证据。
